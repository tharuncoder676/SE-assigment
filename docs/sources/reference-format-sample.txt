[Heading 2] 2. Application of Course Knowledge (20 Marks)
[Normal] Hash Functions, Digital Signatures, Kerberos & X.509
[Normal] Hash Function (SHA-256) – computed on the same plaintext “HELLO” to demonstrate the avalanche effect:
--- TABLE ---
SHA-256("HELLO")  = 3733cd977ff8eb18b987357e22ced99f46097f31ecb239e878ae63760e83e4d5 SHA-256("HELLP")  = d37f1f826f924dcd23aacbdc875edd4808b9e118d35adb9dce1c80cb23c4a9c1   Changing a single character (O -> P) completely changes the digest, confirming the hash reliably detects even minor tampering with the message.
--- END TABLE ---
--- TABLE ---
Sign:   S = h^d mod n = 5^7 mod 33  = 14   (sender signs digest with private key d) Verify: h' = S^e mod n = 14^3 mod 33 = 5   (receiver verifies with public key e)   Since h' = h, the signature is valid: the message came from the holder of the private key and was not altered (integrity + authentication + non-repudiation).
--- END TABLE ---
[Normal] Kerberos – provides ticket-based authentication using a trusted Key Distribution Center (KDC), split into an Authentication Server (AS) and Ticket-Granting Server (TGS):
[List Paragraph] Client sends a request to the AS for a Ticket-Granting Ticket (TGT), authenticating with a password-derived key.
[List Paragraph] AS returns a TGT (encrypted with the TGS's secret key) and a session key (encrypted with the client's key).
[List Paragraph] Client presents the TGT and an authenticator to the TGS to request a service ticket for a specific server (e.g., the internal database).
[List Paragraph] TGS issues a service ticket (encrypted with the target server's key) plus a new session key.
[List Paragraph] Client presents the service ticket and authenticator directly to the target server.
[List Paragraph] Server decrypts the ticket, verifies the authenticator, and both sides now share a session key — mutual authentication achieved without sending passwords over the network.
[Normal] X.509 – defines the standard format for public-key certificates used to bind a public key to an identity (e.g., the company's web/mail server). Key fields include:
[List Paragraph] Version and Serial Number – certificate format version and a unique identifier.
[List Paragraph] Issuer – the Certificate Authority (CA) that signed the certificate.
[List Paragraph] Validity Period – “not before” / “not after” dates.
[List Paragraph] Subject – the entity the certificate identifies (e.g., mail.company.com).
[List Paragraph] Subject Public Key Info – the public key and algorithm (e.g., RSA-2048).
[List Paragraph] Signature Algorithm & CA Signature – proves the certificate itself has not been tampered with.
[Normal] In this design, X.509 certificates issued by an internal or trusted CA let employees' browsers and mail clients verify that they are really talking to the organization's web and mail servers, preventing impersonation.
[Normal] Secure Email (PGP / S/MIME)
[Normal] PGP (Pretty Good Privacy) message flow for an outgoing employee email:
[List Paragraph] Hash the message (SHA-256) and sign the digest with the sender's private key (authentication + non-repudiation).
[List Paragraph] Compress the message + signature (saves bandwidth, adds minor cryptanalytic resistance).
[List Paragraph] Generate a random one-time session key and encrypt the compressed data with a symmetric cipher (e.g., AES) using that key (confidentiality).
[List Paragraph] Radix-64 (Base64) encode the result so it can travel safely through email systems, then send.
[Normal] S/MIME follows the same cryptographic idea (hash + sign, then symmetric-encrypt the body and RSA-encrypt the session key) but differs from PGP mainly in trust model and packaging: S/MIME relies on a hierarchical X.509 CA structure (matching the certificates described under CO3) and uses standard CMS/MIME encoding, whereas PGP uses a decentralized “web of trust” and its own OpenPGP packet format. For a corporate deployment where the organization already operates an internal CA, S/MIME integrates more naturally; PGP is often preferred for cross-organization or individual use where a central CA is not available.
[Normal] Network Security Strategies
[Normal] Network security strategies are designed to protect enterprise systems from threats such as viruses, worms, unauthorized access and network attacks. A firewall is used to filter incoming and outgoing traffic and separate the Internet, DMZ and internal network. IDS (Intrusion Detection System) continuously monitors network traffic and generates alerts when suspicious activity is detected, while IPS (Intrusion Prevention System) can automatically block malicious traffic. Malware defence is also used to detect and remove viruses, worms and other harmful software. By combining firewalls, IDS/IPS and malware protection, the organization can achieve a layered and effective network security architecture.

[Normal] Q2. Which security technique was most challenging to implement and why?
[Normal] The Kerberos ticket-exchange sequence and thprivate-exponent calculation (finding d as the modular inverse of e) were the most conceptually demanding, since both require tracking several dependent values (tickets/session keys, or e, φ(n) and d) correctly across multiple steps before the mechanism can be validated end-to-end.
[Normal] Q3. If you were given additional time and resources, what would you improve?
[Normal] With more time, the design would be validated with real tools end-to-end — for example, configuring actual pfSense firewall rules and Snort signatures in a lab network, and generating full-size (2048-bit) RSA/X.509 certificates with OpenSSL — rather than the small illustrative numbers used here for hand-verifiable calculations.
[Normal] Q4. How can the proposed security architecture be improved for a larger organization?
[Normal] For a larger organization, the design would add: redundant/load-balanced firewalls and IDS/IPS sensors for availability, a centralized Security Information and Event Management (SIEM) system to correlate alerts across the whole network, a formally managed internal Certificate Authority with automated certificate renewal, multi-factor authentication layered on top of Kerberos, and network segmentation (VLANs) per department to further contain any breach.
